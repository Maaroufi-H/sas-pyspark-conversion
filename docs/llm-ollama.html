Usa LLM Ollama fallback

LLM locale on-premise per blocchi SAS non convertibili dalle regole deterministiche.

🔒 Tutti i dati rimangono sulla rete interna — Ollama gira localmente sul server/VM.

Cosa fa

Quando il motore deterministico (Livello 1) classifica un blocco come non convertibile, l'LLM Ollama viene chiamato come fallback per tentare una conversione generativa. Il codice risultante è marcato [LLM-generated] per indicare che richiede revisione manuale.

Logica di attivazione

  1. Il motore deterministico analizza il blocco con le regole JSON
  2. Se convertibile=SI → genera PySpark standard
  3. Se convertibile=NO e LLM attivo → chiama OllamaConverter.convert()
  4. Se Ollama risponde → usa il codice generato (marcato [LLM-generated])
  5. Se Ollama non risponde → genera un blocco # TODO

Come funziona internamente

  • Chiama GET /api/tags per verificare che Ollama sia attivo (timeout: 3s)
  • Costruisce un prompt con fino a 5 esempi di correzioni manuali precedenti (few-shot)
  • Chiama POST /api/generate con stream: false (timeout: 120s)
  • Restituisce il codice Python generato

Configurazione (llm_config.json)

{
  "strategy": "auto",
  "ollama": {
    "host": "http://localhost:11434",
    "model": "codestral"
  }
}
ParametroDescrizione
ollama.hostURL server Ollama (default: http://localhost:11434)
ollama.modelModello da usare (es. codestral, deepseek-coder:6.7b)

Variabili d'ambiente equivalenti: OLLAMA_HOST, OLLAMA_MODEL.

Limitazioni e problemi pending

⚠ Punti di attenzione:
  • Qualità variabile: codice corretto in circa 60-80% dei casi. Revisione manuale sempre consigliata.
  • Tempo di risposta: 5-60 secondi per blocco a seconda del modello.
  • RAM: modelli 7B+ richiedono GPU o molta RAM.
  • Nessuna validazione sintattica: il codice Python generato non viene verificato prima di essere inserito nell'output.
  • Feedback/apprendimento: le correzioni manuali si salvano in learning_db.jsonl via OllamaConverter.record_correction().
