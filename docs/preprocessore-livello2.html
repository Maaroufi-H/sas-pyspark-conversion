Pre-processore Macro Livello 2 opzionale

Risolve le macro variabili SAS e srotola i cicli %do prima della conversione.

Cosa fa

Il pre-processore Livello 2 trasforma il codice SAS in un file "piatto" senza macro variabili irrisolte, così il motore deterministico (Livello 1) ottiene un input pulito e produce conversioni con affidabilità più alta.

  • Raccoglie %let var = valore;
  • Risolve &var (singolo ampersand)
  • Risolve &&var&i (doppio ampersand — due passate, come SAS reale)
  • Srotola %do i=1 %to N; ... %end; quando N è noto
  • Valuta %sysfunc(int(...)) per determinare limiti numerici

Algoritmo — 5 passate

PassataFunzioneEsempio
1_collect_let_statements()%let nid=3; → {"nid":"3"}
2_resolve_sysfunc_int()%sysfunc(int(&var)) → valore numerico
3_resolve_double_ampersand()&&id_prodotto&i → id_prodotto2
4_unroll_do_loops()%do i=1 %to 3; ... %end; → 3 copie
5_resolve_single_ampersand()&var → valore o lasciato invariato

Come si attiva

Nella webapp: spunta "Pre-processore macro Livello 2" prima di cliccare Converti.

Da riga di comando:

python sas_macro_preprocessor.py INPUT/code.sas \
       --output INPUT/code.resolved.sas \
       --macro-vars nid=3 livAgregg=1

Parametri

ParametroDefaultDescrizione
known_vars{}Variabili macro pre-note (es. {"nid": "3"})
max_loop_iterations50Limite massimo di iterazioni per %do loop

Limitazioni e problemi pending

⚠ Le seguenti situazioni NON sono ancora gestite:
  • %macro con argomenti: le chiamate a macro parametrizzate (es. %importa_dati(flusso=A)) non vengono espanse.
  • %if/%else condizionali: solo il ramo attivo è mantenuto se la condizione è risolvibile; altrimenti entrambi i rami restano nel codice.
  • Cicli con limiti non numerici: se N dipende da &sqlobs o da una query, il ciclo non viene srotolato.
  • %include: i file inclusi non vengono letti automaticamente.
  • Triplo ampersand (&&&var): non gestito.
