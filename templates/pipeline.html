Come funziona il Convertitore SAS → PySpark

Architettura a 3 livelli: pre-processore macro, motore deterministico, LLM locale come fallback

⚙️ L0 — Pre-processore Macro

Il pre-processore risolve staticamente le macro SAS prima che il parser analizzi il codice. Va attivato manualmente con il flag "Pre-processa macro" nella UI.

  • 🔴 Espansione variabili macro &var con risoluzione singola
  • 🔴 Doppia risoluzione &&var → &val → valore finale
  • 🔴 Direttive %let nome = valore;
  • 🔴 Loop %do i = 1 %to &n; ... %end;
  • 🔴 5 passaggi sequenziali: tokenizzazione, risoluzione, sostituzione, validazione, output

Limitazione attuale: macro con logica condizionale complessa nel corpo (%if %then annidati) non sono sempre risolvibili staticamente — vengono passate a L1 senza espansione.

🔄 Parametrizzazione: Variabili Macro SAS

Il pre-processore L0 risolve staticamente la parametrizzazione SAS prima di passare il codice al parser. Il processo avviene in 5 passi sequenziali:

  • 1️⃣ Risoluzione %let — raccoglie le definizioni di variabili macro (%let var = valore;) e le memorizza in un dizionario interno.
  • 2️⃣ Espansione &var — sostituisce ogni &nomevariabile con il suo valore risolto dal dizionario.
  • 3️⃣ Doppia risoluzione &&var — gestisce riferimenti indiretti: &&var risolve prima &var, poi usa il risultato come nuovo nome variabile da risolvere.
  • 4️⃣ Espansione %do/%to/%end — srotola i loop macro generando il codice ripetuto per ogni iterazione. Esempio: %do i = 1 %to 3; produce 3 copie del corpo.
  • 5️⃣ Pulizia direttive — rimuove le istruzioni %let e %macro/%mend residue dopo l'espansione, lasciando solo il codice SAS espanso pronto per il parser L1.

Parametri di funzione: le macro SAS con parametri (%macro nome(param1, param2)) vengono convertite da L1 in funzioni Python con gli stessi parametri:

/* SAS */ %macro calcola_sconto(prezzo, percentuale); &prezzo * (1 - &percentuale / 100) %mend calcola_sconto; # PySpark generato def macro_calcola_sconto(prezzo, percentuale, spark): return prezzo * (1 - percentuale / 100)

Limitazione nota: macro con logica condizionale complessa (%if %then nel corpo) non vengono risolte staticamente. Il blocco viene passato a L1 con i token macro non espansi e marcato come # TODO se non convertibile.

⚡ L1 — Motore Deterministico

Il cuore del sistema: analizza il SAS in blocchi tipizzati, applica le regole di conversione definite in JSON, e produce codice PySpark senza mai chiamare un LLM.

  • 🟢 Parser gerarchico: scompone il SAS in un albero di blocchi con range di righe e profondità
  • 🟢 Regole JSON (regole_classificazione.json): ogni tipo di blocco ha regole di convertibilità e affidabilità
  • 🟢 DATA STEP semplici: SET, WHERE, KEEP, DROP, RENAME, assegnazioni
  • 🟢 PROC SQL base: CREATE TABLE AS SELECT, INSERT INTO, DROP TABLE
  • 🟢 PROC SORT: orderBy() con ASC/DESC
  • 🟢 PROC MEANS / FREQ / PRINT: aggregazioni e statistiche descrittive
  • 🟢 MERGE semplici: join binario con BY
  • 🟢 %MACRO / %MEND: convertite in funzioni Python def macro_nome(...)

I separatori di blocco nell'output usano # ══ per delimitare visivamente ogni sezione convertita. I blocchi non gestiti emettono un commento # TODO: REVISIONE MANUALE NECESSARIA.

# ══════════════════════════════════════════════════════ # DATA STEP: output_table [riga 12–28] # ══════════════════════════════════════════════════════ output_table = spark.table("input_table")\ .filter(F.col("amount") > 0)\ .select("id", "amount", "date") # ============================================================ # TODO: REVISIONE MANUALE NECESSARIA # Motivo : RETAIN / FIRST. LAST.: usare Window functions # ============================================================

🧠 L2 — LLM Locale (Ollama)

Il livello LLM è un fallback opzionale per i blocchi SAS che il motore deterministico non riesce a convertire. Va attivato manualmente con il flag "Usa LLM".

{% if ollama_ok %} ● LLM attivo — {{ llm_model }} {% else %} ● LLM non disponibile — controlla Ollama {% endif %}
  • 🟢 Modello attuale: {{ llm_model }} via Ollama su localhost:11434
  • 🟢 Attivabile per singola richiesta — non obbligatorio
  • 🟢 Usato come fallback: L1 tenta prima, L2 interviene solo sui blocchi rimasti TODO
  • 🟢 Output LLM marcato con # [LLM-generated] per distinguerlo dal codice deterministico
  • 🟢 Tutti i dati restano on-premise — nessun invio a LLM cloud

Limitazione: la qualità dipende dalla RAM disponibile e dal modello caricato. Su infrastruttura CPU-only (Azure B2s, 2 vCPU) la velocità è ~7.5 tok/s: ogni blocco SAS impiega ~30s con num_predict=200.

# [LLM-generated] righe 15–22 | RETAIN / FIRST. LAST.: usare Window functions from pyspark.sql import Window from pyspark.sql.functions import col, sum as F_sum window_spec = Window.orderBy("date") running_totals = sales_data.withColumn( "cumulative_sales", F_sum("daily_sales").over(window_spec) )

📋 Costrutti ancora in sospeso

Alcuni costrutti SAS non hanno ancora una conversione automatica affidabile. Vengono marcati # TODO nell'output per revisione manuale.

Non supportato SQL dinamico con macro SAS nel corpo della query (%if/%then, %do dentro PROC SQL)
Non supportato CALL EXECUTE e generazione dinamica di codice SAS a runtime
In progress RETAIN / FIRST. / LAST. — suggerimento Window functions generato, conversione automatica non garantita
In progress Macro SAS con parametri multipli e logica condizionale ricorsiva nel corpo
Non supportato PROC REPORT e PROC TABULATE — output tipografico senza equivalente diretto in PySpark
In progress PROC FORMAT — formati SAS custom, parzialmente mappati su F.when()
Non supportato Macro di sistema complesse: %SYSFUNC, %EVAL con espressioni aritmetiche, %SCAN, %INDEX
Non supportato PROC IML — algebra matriciale SAS, nessun equivalente automatico in PySpark

🎉 Come leggere l'output generato

Il codice PySpark generato usa un sistema di annotazioni visive per indicare la provenienza e l'affidabilità di ogni blocco convertito.

  • ⚫ # Commenti grigi — separatori di blocco # ══, intestazioni di sezione. Generati deterministicamente da L1.
  • 🟡 # TODO gialli — blocchi non convertiti automaticamente. Richiedono revisione manuale. Contengono il codice SAS originale come riferimento.
  • 🟢 # [LLM-generated] verdi — blocchi convertiti dal modello LLM locale. Da verificare: possono contenere nomi di tabelle generici (sales_data) al posto di quelli reali.
  • 🔴 Keyword viola — parole chiave Python (def, return, if, …) evidenziate nel viewer.

I blocchi # TODO contengono sempre il codice SAS originale nelle righe di commento sottostanti — usalo come riferimento per la riscrittura manuale.
